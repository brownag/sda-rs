## Notes
- Task scope permits only the feasibility report, this TODO, and scratch under `/tmp/opencode/sda-rs-plan15-parser/`; no implementation or dependency changes.
- `src/transpiler/mod.rs` currently parses T-SQL through `DialectType::TSQL`, validates AST via DFS, then rewrites and generates SQLite SQL. This is not evidence of DuckDB-dialect equivalence.
- DuckDB executor gate currently accepts simple SELECT and a narrow temporary-table lifecycle, rejecting comments, quoted forms, and multi-statement input in its per-statement validator.
- Existing security probes show pinned DuckDB accepts comments, quoted identifiers/literals, compound batches, and in-memory ATTACH directly; temp-table lifecycle is exercised in one connection.
- Use offline/local synthetic probes only. Do not claim exhaustive security or expose DuckDB to HTTP.

# 6.2.1 — Decode and validate GeoPackageBinary
## Goal
Add a small, independently testable GeoPackageBinary header decoder that validates its header and exposes the bounded WKB payload without changing query semantics.
## TODO items
- [x] Define the decoder result/error interface and GeoPackageBinary header constants in `src/gpkg_geometry.rs`.
- [x] Validate minimum header size, `GP` magic, supported version, reserved flag bits, and envelope indicator; return explicit errors for malformed headers.
- [x] Decode byte order and SRS identifier from header flags and fields.
- [x] Compute optional envelope length from indicator and dimensionality, checking arithmetic and input bounds before slicing.
- [x] Expose the remaining WKB payload with an empty-geometry indication where the GeoPackage empty flag is set; reject missing/truncated payloads without reinterpreting arbitrary blobs.
- [x] Add focused unit tests in `src/gpkg_geometry.rs` for valid little-/big-endian headers, envelope variants, empty geometry, WKB extraction, and invalid/truncated values; run `cargo test gpkg_geometry`.
- [x] Export the new module from `src/lib.rs` and run `cargo fmt --check`.
- [x] Run `git diff --check`.
## Notes
- Scope is limited to `src/gpkg_geometry.rs` and `src/lib.rs`; unit tests belong in `src/gpkg_geometry.rs`.
- Keep parsing independent of SpatiaLite. Do not edit `src/spatial.rs`, `src/serializer.rs`, query semantics, or wire response code.
- Existing `GeomFromGPB` uses are not a general decoder contract; this task adds explicit validation without silently accepting arbitrary blobs.
- Acceptance commands: `cargo test gpkg_geometry`; `cargo fmt --check`; `git diff --check`.

# Task 5.1.1 Micro-plan — revised transaction lifecycle

## Goal

Enforce the SQLite authorizer policy for submitted SQL while retaining an executor-owned transaction boundary: successful batches commit, and any execution failure rolls the entire batch back before the error is returned.

## Review notes

- The current `?` exits in `execute_on` drop the transaction while the authorizer remains active; the drop-triggered rollback is therefore subject to the authorizer and does not reliably restore temp-table state.
- The current success path removes the authorizer before `commit`, which explains why commit works but leaves the failure path asymmetric.
- The revised implementation must close that lifecycle gap without broadening authorizer permission for submitted transaction-control SQL.

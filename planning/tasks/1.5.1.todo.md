# Task 1.5.1 Micro-plan — Spatial AOI transpilation and acceptance

## Goal
Integrate AOI geometry and WGS84 mukey spatial SQL rewrites using per-request spatial capability and dynamic GeoPackage geometry metadata, then verify deterministically through the in-process router.

## Context and decisions
- Branch: `feature/sqlite-mvp`; dependencies through 1.4.2 are complete.
- Edit `src/transpiler/spatial.rs`, `src/transpiler/mod.rs`, `src/routes.rs`, `src/spatial.rs`, and `tests/sda_mvp.rs`.
- `execute_query_blocking` already calls a pre-transpile closure with `&SpatialCapability`, after rejecting raw spatial SQL when unavailable. Keep its request-local lifecycle and blocking boundary unchanged.
- Orchestrator expanded scope to retain GeoPackage geometry metadata per table, then select the `mupolygon` entry for the mukey TVF. Do not rely on the first row in `gpkg_geometry_columns`.
- The current transpiler pipeline validates T-SQL, folds variables, rewrites temp tables, then generates SQLite. Add spatial rewriting against this already validated/folded AST before generation; pass request capability and metadata from the route closure.
- polyglot-sql 0.14.1 represents AST nodes as `Expression` variants; relevant concrete shapes include `In { this, expressions, query, ... }` and `MethodCall { this, method, args }`. Validate parser-produced shapes for all required source forms in focused tests before relying on them.
- No `mod_spatialite` extension is available in this environment. Verify SQL rewrite outputs and structured unavailable-capability response; report live spatial execution unavailable, not passed.
- Planning artifacts are tracked separately from implementation. Do not commit or perform remote actions.

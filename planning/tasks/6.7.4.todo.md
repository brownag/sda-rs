# 6.7.4 — Diagnose `MAX` in generated scalar mukey WKT SQL

## Goal

Locate the `MAX` behind the SQLite HTTP 500 in `SDA_Get_MupolygonWktWgs84_from_Mukey('inside')` and determine whether a nonnumeric argument causes the failure or merely exposes SQL that also fails for numeric arguments. Fix only an established in-scope cause.

## Findings

- T-SQL parsing rewrites the template's `CAST(... AS TEXT)` into `VARCHAR(MAX)`, which SQLite rejects with `near "MAX": syntax error`. The key argument does not cause that syntax error.
- `NULL` parses as `Expression::Null`, not `Expression::Literal`; the initial scalar TVF validator rejected it. Validation now accepts both literal and NULL AST nodes, and SQL equality naturally returns no rows for NULL.
- The fixture's duplicate-table diagnosis was mistaken. `InitSpatialMetaData(1)` in this environment does not create `gpkg_geometry_columns`; create the test GeoPackage metadata table once after SpatiaLite initialization and populate it.

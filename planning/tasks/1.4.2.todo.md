# Task 1.4.2 Micro-plan — Optional spatial initialization and GeoPackage metadata

## Goal
Add a module-local spatial capability/metadata API in `src/spatial.rs`, keeping registration and executor integration out of scope.

## Context and constraints
- Branch: `feature/sqlite-mvp`; planning artifacts are tracked separately.
- Dependencies 1.2.1 and configured-path executor are complete.
- `src/lib.rs` has no spatial registration. Routes currently construct executor work without spatial configuration; executor opens a `rusqlite::Connection` internally.
- `Config` already exposes optional `spatial_extension` and `geometry_column`.
- Only edit `src/spatial.rs` and tests local to that module. Do not alter module registration, executor, routes, config, or other files.
- Existing `target/` is untracked and must be left untouched.

## Tasks
1. Define module-local structured spatial capability and metadata/error types, including a clear error for spatial-required operations when spatial functions are unavailable.
2. Add a small connection initialization interface accepting a SQLite connection and optional extension path; load only when configured, convert load failures into the structured capability error, and expose whether spatial support is available.
3. Query `gpkg_geometry_columns` dynamically for table name, geometry-column name, and SRS ID; tolerate absent metadata/table for ordinary SQLite databases. Keep geometry override handling explicit if supported by this local interface; do not assume a fixed geometry name.
4. Add module tests for absent metadata, discovered metadata and SRID, configured-but-unavailable extension, and the structured missing-capability error.
5. Run focused `cargo test spatial::` once module is registered by the orchestrator; report local SpatiaLite availability and, only if available, smoke-test a real spatial function.

## Stop condition / coordination
Task specification requires module registration and executor initialization integration eventually, but explicitly prohibits changing those files here. Stop after the `src/spatial.rs` API and tests are planned/implemented. Report the API contract needed by the orchestrator; require its authorization and a separate task/scope before touching shared registration or executor files.

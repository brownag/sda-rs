# Task 1.3.1 Micro-plan — SDA Query Request Routes

## Goal

Implement both SDA tabular POST routes, accepting JSON and URL-encoded requests, normalizing query/format keys case-insensitively, handling query echo, and invoking the existing transpiler and SQLite executor with structured errors.

## Preconditions and scope

- Dependencies 1.2.1 and 1.2.2 are complete, as recorded in `planning/STATE_1.md`.
- Edit `src/routes.rs`, `src/request.rs`, and `src/lib.rs` only for replacing stub handlers and wiring routes/serializer. No other files may be created.
- Task 1.3.2 runs first and registers the serializer module. Preserve that registration; do not edit serializer internals.
- Do not edit `main.rs`, `config.rs`, executor, transpiler, serializer internals, or planning sources other than this micro-plan.
- Keep the existing `target/` untracked state untouched. No remote actions.

## Implementation steps

1. Inspect existing public executor/transpiler APIs and dependency features needed by handlers; keep integration within the two authorized files.
2. Define request parsing in `src/request.rs` for JSON and `application/x-www-form-urlencoded`, recognizing `query`/`QUERY` and `format`/`FORMAT` case-insensitively. Represent missing or malformed input as a structured request error.
3. Implement route handlers in `src/routes.rs` for the two endpoint paths, invoking transpilation before SQLite execution and mapping parse, transpile, and execution failures to structured HTTP responses.
4. Handle `FORMAT=~` by returning submitted SQL as `text/plain` without transpiling or executing it; do not expand macros.
5. Wire both endpoint routes to the new handlers in `src/lib.rs`, retaining middleware.
6. Add in-module in-process router tests for both endpoints and body encodings, mixed-case keys, missing query, unsafe SQL, and query echo without a TCP listener.

## Verification

- Run focused tests: `cargo test routes::`.
- Run `cargo fmt --check` and `git diff --check` for the scoped changes.
- Confirm implementation changes are limited to `src/routes.rs`, `src/request.rs`, and authorized route wiring in `src/lib.rs`.
- Planning artifacts are tracked separately; commit this planning artifact separately from any implementation commit.

## Stop condition

If required wiring needs files beyond the authorized `src/lib.rs` edits, stop before implementation and report the precise blocker for orchestrator authorization.
